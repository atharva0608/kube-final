# cluster_inventory

## Purpose
The `cluster_inventory` module is the persistence and serving layer for all Kubernetes resource data collected by the BalanceKube agent. It exists as a separate module because the raw inventory (nodes, pods, controllers, PVCs, PDBs) represents a distinct data domain that must be snapshot-scoped, versioned, and made queryable for both the frontend and downstream Phase 2/3/4 pipeline stages without any of those stages needing to understand agent wire format.

## Responsibilities
- Receive full inventory snapshot payloads pushed by the agent via the REST API
- Parse, validate, and normalize each resource type into its canonical database schema
- Store all resources as snapshot-scoped rows (keyed by `snapshot_id`) to support historical diffing and rollback
- Serve resource data to the frontend via paginated, filterable list endpoints
- Initialize per-cluster inventory tracking records when a new cluster is registered
- Track node capacity and allocatable resources (CPU millicores, memory MiB, ephemeral storage GiB, GPU count)
- Capture pod scheduling context: node affinity, pod anti-affinity, tolerations, topology spread constraints
- Record PVC zone-locking metadata (storage class, access mode, bound zone) critical for rescheduling decisions
- Record PDB `minAvailable` / `maxUnavailable` constraints and current `disruptionsAllowed` count
- Associate pods with their owning controller (Deployment / StatefulSet / DaemonSet / Job / CronJob) via `ownerReferences`

## Inputs

### From Agent (REST)
- **Source**: `POST /api/v1/agents/:id/inventory`
- **Format**: `InventoryPayload` TypeScript type:
```typescript
{
  snapshotId: string;           // UUID v4, generated by agent
  clusterId: string;
  collectedAt: string;          // ISO 8601
  schemaVersion: string;        // e.g. "1.4"
  collectionCycleId: string;    // UUID v4, generated once per collection trigger; reused on retries
  nodes: NodeRecord[];
  pods: PodRecord[];
  deployments: DeploymentRecord[];
  statefulsets: StatefulSetRecord[];
  daemonsets: DaemonSetRecord[];
  pvcs: PVCRecord[];
  pdbs: PDBRecord[];
  namespaces: NamespaceRecord[];
}
```

### Node record key fields
```typescript
{
  name: string;
  instanceType: string;         // e.g. "m5.xlarge"
  availabilityZone: string;
  region: string;
  capacityCpu: number;          // millicores
  capacityMemory: number;       // MiB
  capacityEphemeralStorage: number; // GiB
  capacityGpu: number;
  allocatableCpu: number;
  allocatableMemory: number;
  allocatableEphemeralStorage: number;
  labels: Record<string, string>;
  taints: { key: string; value?: string; effect: string }[];
  conditions: { type: string; status: string; reason?: string }[];
  providerNodeId: string;       // AWS instance ID (i-xxxx)
  spotInstance: boolean;
}
```

### Pod record key fields
```typescript
{
  name: string;
  namespace: string;
  nodeName: string;
  phase: string;
  ownerKind: 'Deployment' | 'StatefulSet' | 'DaemonSet' | 'Job' | 'ReplicaSet' | null;
  ownerName: string;
  containers: {
    name: string;
    image: string;
    requestsCpu: number;        // millicores
    requestsMemory: number;     // MiB
    limitsCpu: number;
    limitsMemory: number;
    requestsGpu: number;
  }[];
  affinity: object;             // raw K8s Affinity JSON
  tolerations: object[];
  topologySpreadConstraints: object[];
  labels: Record<string, string>;
  annotations: Record<string, string>;
}
```

### From NATS (Events)
- **Source**: `cluster.registered` event
- **Action**: Initialize an empty inventory tracking record for the new cluster (sets `inventory_status = PENDING_FIRST_PUSH`)

## Outputs

### API Responses (to frontend)
- `GET /api/v1/clusters/:id/nodes` → paginated `NodeRecord[]` with allocatable + capacity breakdown
- `GET /api/v1/clusters/:id/pods` → paginated `PodRecord[]` grouped by controller
- `GET /api/v1/clusters/:id/deployments` → `DeploymentRecord[]` with replica counts and resource totals
- `GET /api/v1/clusters/:id/statefulsets` → `StatefulSetRecord[]` with PVC binding summary
- `GET /api/v1/clusters/:id/daemonsets` → `DaemonSetRecord[]` with per-node scheduling status
- `GET /api/v1/clusters/:id/pvcs` → `PVCRecord[]` with zone, storage class, access mode
- `GET /api/v1/clusters/:id/pvcs` → `PDBRecord[]` with minAvailable, maxUnavailable, disruptionsAllowed

### Database Writes
- Inserts rows into all inventory tables scoped to the incoming `snapshot_id`
- Previous snapshot rows are retained (not deleted) to support drift comparison

### No Events Published
The cluster_inventory module does not publish NATS events. It is a pure data persistence layer; event publishing is the responsibility of `snapshot_assembly` after it assembles the full snapshot.

## Events Produced
N/A — this module does not publish events. Data written here is consumed by `snapshot_assembly`.

## APIs
| Method | Path | Auth | Description |
|---|---|---|---|
| `POST` | `/api/v1/agents/:id/inventory` | Agent token | Accept full inventory push from agent. Validates token. Upserts all resource types in a single transaction. Triggers `snapshot_assembly` via BullMQ job. Returns `{ snapshotId, accepted: true }`. |
| `GET` | `/api/v1/clusters/:id/nodes` | JWT | List nodes for the latest snapshot. Supports query params: `?az=`, `?instanceType=`, `?spot=true`. Paginated (default 50). |
| `GET` | `/api/v1/clusters/:id/pods` | JWT | List pods for the latest snapshot. Filterable by `?namespace=`, `?ownerKind=`, `?nodeName=`. Paginated. |
| `GET` | `/api/v1/clusters/:id/deployments` | JWT | List deployments with replica summary. |
| `GET` | `/api/v1/clusters/:id/statefulsets` | JWT | List statefulsets with PVC binding summary. |
| `GET` | `/api/v1/clusters/:id/daemonsets` | JWT | List daemonsets with per-node scheduling summary. |
| `GET` | `/api/v1/clusters/:id/pvcs` | JWT | List PVCs with zone and access mode metadata. |
| `GET` | `/api/v1/clusters/:id/pdbs` | JWT | List PDBs with current disruption budget status. |
| `GET` | `/api/v1/clusters/:id/namespaces` | JWT | List namespaces with labels. |

> **Idempotency (`POST /api/v1/agents/:id/inventory`):** The request must include a `collection_cycle_id` UUID field. This UUID is generated once per collection trigger by the agent and reused on all retry attempts. The server enforces a unique constraint on `(cluster_id, collection_cycle_id)`. On duplicate: if same `collection_cycle_id`, return 200 with existing `snapshot_id`; if different UUID with same node/pod data, treat as a new snapshot normally.

## Configuration

| Environment Variable | Default | Description |
|---|---|---|
| `INVENTORY_MAX_NODES` | `5000` | Maximum nodes accepted per inventory push (guards against oversized payloads) |
| `INVENTORY_MAX_PODS` | `50000` | Maximum pods accepted per inventory push |
| `INVENTORY_SCHEMA_VERSION_MIN` | `1.0` | Minimum agent schema version accepted; older agents are rejected with `426 Upgrade Required` |
| `INVENTORY_PAGE_SIZE` | `50` | Default page size for list endpoints |
| `INVENTORY_MAX_PAGE_SIZE` | `500` | Maximum page size for list endpoints |
| `SNAPSHOT_RETENTION_DAYS` | `7` | Days to retain old snapshot rows before pruning |

## Error Handling

| Scenario | Behavior |
|---|---|
| Invalid or expired agent token | `401 Unauthorized`; log `INVENTORY_AUTH_FAILED` with agent ID |
| `InventoryPayload` schema validation failure | `400 Bad Request` with Zod error array; inventory push rejected entirely — no partial writes |
| `collection_cycle_id` already exists and matches (idempotent delivery) | Server returns 200 with the existing `snapshot_id`. The agent's original write succeeded but the response was lost. No duplicate snapshot is created. |
| DB transaction failure during insert | Full rollback of all resource tables for this snapshot; 500 returned to agent; agent retries on next cycle with the SAME `collection_cycle_id`. |
| `cluster.registered` event handler fails | Logged; inventory status remains in default state; first successful push will self-initialize |
| Oversized payload (exceeds node/pod limits) | HTTP 413 with body `{ error: 'INVENTORY_LIMIT_EXCEEDED', current_pods: N, current_nodes: N, limit_pods: 50000, limit_nodes: 5000 }`. Agent respects `Retry-After: 1800` header (30 minutes). Operators may contact support to increase limits via `cluster_settings.inventory_max_pods_override` / `cluster_settings.inventory_max_nodes_override` (nullable columns — null = use global env var default). |
| Missing `snapshot_assembly` BullMQ enqueue | Logged as `SNAPSHOT_ASSEMBLY_ENQUEUE_FAILED`; retry via background reconciliation worker that polls for unassembled snapshots |

## Future Enhancements
- **Incremental / delta inventory pushes**: Allow agents to push only changed resources instead of the full snapshot, reducing bandwidth for large clusters
- **Custom Resource Definition (CRD) support**: Store CRD instances (e.g., Argo Rollouts, KEDA ScaledObjects) to inform eligibility decisions
- **Resource history API**: Expose a time-series API for how resource counts and capacity have changed over time per cluster
- **Node pool / managed node group metadata**: Ingest ASG/MNG names and scaling policies to support execution-time capacity decisions
- **Real-time inventory streaming**: Push inventory changes over WebSocket to the frontend as they arrive, eliminating dashboard polling
